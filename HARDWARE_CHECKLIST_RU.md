# Проверка Voyah Manager на реальном ГУ

Статус интерфейса 2.1: ГУ не подключалось. Этот список фиксирует оставшиеся
проверки автомобиля; результаты имитатора не подтверждают их выполнение.

Версия 2.1 меняет внешний вид и расположение существующих функций. Отмечать
пункты ниже нужно только после проверки на автомобиле или отдельном физическом
стенде. Сначала запишите модель, прошивку, API, способ подключения и версию EXE.

## Интерфейс с подключённым автомобилем

- [ ] Выбранное устройство и статус в верхней панели соответствуют реальной машине.
- [ ] После подключения и переподключения обновляются совместимость каталога,
      модель клавиатур и доступность действий; данные предыдущего ГУ не остаются.
- [ ] Значки навигации управляют ГУ; подсказки понятны и доступны в RU/EN.
- [ ] При масштабе Windows 100/125/150% видно текущий этап, прогресс и отмену.
- [ ] При уменьшении окна доступны значки меню, главные действия, таблицы и диалоги.
- [ ] Отключённая анимация не мешает выбору устройства, раскрытию меню и работе команд.
- [ ] Полный журнал доступен из любого раздела; переключение раздела не меняет
      устройство текущего задания и не останавливает его.
- [ ] В админ-меню запрещённые операции остаются недоступными через кнопки,
      дополнительные меню, контекстные меню и Drag-and-Drop.

## Обычные функции и установка

- [ ] USB: RSA-подтверждение, serial, model, API, ABI и три дисплея определяются верно.
- [ ] Wi-Fi: проверен адрес своего ГУ; при необходимости протестирован порт 5578.
- [ ] USB → Wi-Fi: адреса интерфейсов показаны, TCP 5555 включён, сессия установлена.
- [ ] Отсоединение кабеля/сети во время чтения останавливает задание и обновляет статус.
- [ ] Инспектор: package/activity сопоставлены с реально открытыми экранами 0/1/2.
- [ ] Руль: шестисекундная запись началась до нажатия, группы результатов соответствуют
      действию; пустые результаты описаны корректно и не трактуются как поломка кнопки.
- [ ] Live: оба вида наблюдения проверены отдельно; фильтр и пауза прокрутки не
      теряют сообщения полной записи; getevent при необходимости проверен с выбранным Root.
- [ ] Сохранён скриншот; проверено соответствие физических и логических экранов.
- [ ] Установлено тестовое приложение, затем его batch/split-вариант, проверен запуск.
- [ ] XAPK/OBB: результат переноса проверен в файловом менеджере.
- [ ] Файлы с пробелами и кириллицей: push → список → pull; содержимое совпадает.
- [ ] Для отдельного тестового пакета проверены freeze/enable, clear и uninstall.
- [ ] Проверены экспорт base/splits и запуск на центральном/пассажирском экране.
- [ ] DPI: сначала прочитаны исходные значения; адресное изменение выполняется только
      при поддержке прошивки и возвращается к исходному состоянию.
- [ ] Private DNS/Captive Portal/Immersive: значения прочитаны, изменены и восстановлены.
- [ ] pm grant/appops: разрешение заявлено тестовым APK, результат проверен на устройстве.
- [ ] Root по выбору: проверены поддерживаемый вариант, отказ и adb unroot.
- [ ] Перезагрузка проверена отдельно; проверены доступность Android и `sys.boot_completed`.
- [ ] Обычный APK: блокировка sys.config.app_install_disabled, --no-streaming,
      установленная версия; RuStore: REQUEST_INSTALL_PACKAGES allow.
- [ ] Каталог настроен на публичный репозиторий; реальная публикация, конфликт SHA,
      обновление со второго ПК и установка клиентом без токена проверены отдельно.
## Системные сценарии — отдельная проверка

- [ ] Клавиатуры: модель, API, ABI, ожидаемые пакеты и два штатных пути подтверждены.
- [ ] Root, disable-verity, повторный Root и remount поддерживаются прошивкой.
- [ ] До создания `.old` хватает места для копирования системного APK; отсутствие
      места приводит к остановке без замены исходного файла.
- [ ] Штатные .old сохранены, копии на ПК совпадают с оригиналами по SHA-256.
- [ ] Клавиатуры обоих экранов: ввод, язык, раскладка и фокус работают после reboot.
- [ ] После замены возвращён SELinux; подтверждены 0:0, 0644 и SELinux-контекст.
- [ ] Откат клавиатур возвращает .old и не включает dm-verity автоматически.
- [ ] Qinggan Settings: проверены DB/WAL/SHM, пересоздание базы и функции автомобиля.
- [ ] Отключение dm-verity отдельно проверено; оно не называется включением verity.
- [ ] Wi-Fi после перезагрузок восстанавливается на том же IP:порту.
- [ ] Отдельно воспроизведена принятая устройством команда reboot с потерей ответа
      ADB по Wi-Fi. Зафиксирован фактический итог, состояние изменённых файлов и
      переход к ожиданию загрузки; исправление не считается подтверждённым по новому UI.
- [ ] Для Qinggan Settings проверено, достаточно ли доступа к `/data` текущего
      сценария без отдельного `adb remount`; пересозданная база открывается штатным провайдером.
- [ ] На стенде проверены незавершённый сценарий и запуск Android после сбоя.

Изменение приборного дисплея, системных пакетов и режимов загрузки проверяется
только отдельно от базового сценария. Эти действия не нужны для проверки подключения.

Известные расхождения с оригинальным установщиком сохранены в
`reverse-output/feature-audit/COMPARISON_RU.md`. Графические эффекты, успешные
тесты имитатора и новые пояснения не закрывают аппаратные пункты этого списка.
