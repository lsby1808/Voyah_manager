# Voyah Manager 2.0.1 — отчёт выпуска

Дата: 14 октября 2026. Проверка выполнена на Windows 11 x64 build 26200.
Сборка предназначена для Windows 10/11 x64; отдельная Windows 10 недоступна.
Реальное ГУ не подключалось. Системные сценарии не прошли аппаратную проверку.

## Артефакты и воспроизводимость

- `dist/Voyah Manager.exe` — автономная однофайловая сборка, версия 2.0.1.
- Итоговые размер, SHA-256 EXE и SHA-256 исходника: `dist/release_manifest.json`.
- Размер итогового EXE: 128 630 884 байт (около 123 МиБ).
- SHA-256 итогового EXE: `5685d1f458970bbb520b9b7fca0ff6e6e1c959f00f306d9afaabe41da23df4b5`.
- SHA-256 исходника: `02e82d5d952e4d096cd63619c37b4939fcfff4c69ea944d54cb69feb0f9eade0`.
- Файл контрольной суммы: `dist/Voyah Manager.exe.sha256`.
- Весь код приложения: `voyah_manager.py`.
- В EXE включён `build_manifest.json` с хешем исходника; проверка запуска сравнивает его с выданным файлом.
- Разработка и исходные локальные проверки: Python 3.12.14, PySide6/Qt 6.10.2, PyInstaller 6.22.0.
- Итоговый EXE собран в GitHub Actions с Python 3.12.10, доступным как готовый Windows-пакет в setup-python.
- Серверная сборка скачана из Releases, её SHA-256 проверен; именно она находится в локальной папке dist.
- Исходник обеих сборок совпадает по SHA-256. Зависимости зафиксированы.
- Встроены ADB с DLL, AAPT2, bundletool 1.18.3, Temurin Java 17 и лицензии.
- Authenticode: NotSigned. Подпись не заявляется.
- Версия 1.0 сохранена в `releases/v1`.

Проверены новые функции:

- Ограничения обработчиков установки, файловых изменений, freeze/clear/uninstall, твиков, терминала и клавиатур.

- Валидный и повреждённый JSON, неизвестные поля/команды, типы данных, ETag/304 и сохранение последнего профиля.
- GitHub Raw: чтение публичного JSON, ETag/304, точный Git blob SHA; Contents API: публикация, конфликт SHA, HTTP 401/403/404/409 и сохранность черновика.
- Репозиторий, закреплённый релиз и прямая ссылка; выбор из нескольких APK и digest источника.
- Атомарная загрузка, неверный размер/хеш, отмена, проверка кэша без сети и повреждённый кэш.

- Чтение/запись/удаление тестового секрета в настоящем Windows Credential Manager; секрета нет в QSettings.

ADB в системных тестах — имитатор с файлами, состоянием Android/SELinux и отказами.
GitHub API в тестах публикации из приложения — имитатор Qt-сети.
После подключения GitHub в Codex реально созданы публичный каталог, исходники, тесты,
инструкции и workflow в `lsby1808/Voyah_manager`. Секреты подключения Codex не переносились в EXE.
Метаданные клавиатур в тестах сценариев задаются контролируемым имитатором AAPT2;
обычные APK и архивы дополнительно проверяются настоящими AAPT2/bundletool.

В этой среде стандартный захват вывода pytest/pytest-qt в отдельных запусках
приводил к аварийному завершению Qt в processEvents. Итоговые запуски выполнены
с `-s`; их XML и журналы сохранены. Нативные запуски готового приложения проверялись отдельно.

## Проверка Windows EXE

Сначала собрана и запущена сборка из каталога `staging-v2`, затем однофайловый EXE.
GitHub Actions также собрал и проверил оба варианта на Windows Server 2025 x64.
После публикации итоговый EXE скачан и повторно запущен на текущей Windows 11 x64.
При запуске EXE PATH содержал только Windows/System32 и Windows;
PYTHONHOME, PYTHONPATH и JAVA_HOME были удалены из окружения проверочного процесса.
Принудительно выбран встроенный ADB. Внешние Python/Qt/Java/ADB через PATH не использовались.

В проверке EXE запускаются настоящие `adb version`, `aapt2 version` и Java/bundletool version.
Публичный каталог загружается с raw.githubusercontent.com: реальный HTTPS GET вернул HTTP 200.
В завершающей проверке 2.0.0 GitHub REST API вернул 403 с X-RateLimit-Remaining: 0.
Поэтому в 2.0.1 чтение переведено на GitHub Raw; публикация с токеном остаётся через Contents API.
Сетевая проверка 2.0.1 обращается к самому публичному каталогу.
Готовый EXE прочитал публичный каталог `lsby1808/Voyah_manager`, revision 1:
результат включён в поле catalog каждого итогового report.json.
Первый запуск проверен после переноса отдельного QA-кэша; рабочий каталог пользователя не изменялся.
Совпадение версии, хеша исходника и состава встроенных инструментов фиксируется в report.json.

Масштабирование проверяется через QT_SCALE_FACTOR относительно DPI текущего монитора:
100% = DPR 1.0, 125% = DPR 1.25, 150% = DPR 1.5. Настройки Windows пользователя не менялись.
Снимки всех восьми страниц RU/EN, внутренних страниц инспектора, админ-меню и настроек соединения:

- `qa-v2-exe-100`, `qa-v2-exe-125`, `qa-v2-exe-150`;
- последняя сборка после косметических исправлений: `qa-v2-release-100`, `qa-v2-release-125`, `qa-v2-release-150`;
- запуск без имитатора и без устройства, компактное окно: `qa-v2-release-offline`.

Визуально проверены перенос панелей действий, читаемость RU/EN, длинные названия,
компактное меню, неактивные кнопки и доступность операций над таблицами.
Пустые дубли журналов убраны; общий раскрываемый журнал остаётся внизу.
