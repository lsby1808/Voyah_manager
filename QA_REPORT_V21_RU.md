## Автономность и первый запуск

Нагрузочный прогон подал 20 000 сообщений в наблюдение. После ограничения текста
до отрисовки возврат из паузы занял 62 мс; интерфейс продолжал обрабатывать
события (55 срабатываний контрольного таймера), а видимая запись осталась в
пределах 6000 строк. Исходный буфер для сохранения сохранил сообщения этого
прогона. Максимальный промежуток между контрольными событиями составил 266 мс.
Метрики сохранены в `qa-v21-live-stress.json`.

Сначала собрана и запущена версия в каталоге, затем переносимый onefile EXE.
CI на чистом профиле Windows выполнил оба запуска и реальные команды проверки
встроенных ADB, AAPT2, bundletool и Java. При первой подготовке кеша инструмента
проверка ждёт завершения фонового задания, продолжая обрабатывать события UI.
Дополнительная локальная проверка с искусственной задержкой подготовки на шесть
секунд завершилась успешно: 89 срабатываний таймера интерфейса, все инструменты
запущены, код завершения 0.

Скачанный EXE проверен с PATH, содержащим только Windows/System32 и Windows;
переменные PYTHONHOME, PYTHONPATH и JAVA_HOME исключены. Установленные на ПК
Python, Qt и Java для этих запусков не использовались. Проверка исходника во
встроенном манифесте совпала с локальным файлом и опубликованной сборкой.

## Визуальная приёмка

Все восемь разделов сняты в RU/EN на масштабах **100%, 125%, 150%**.
Сняты четыре сценария инспектора, четыре страницы администратора, настройки
подключения и восстановление. Отдельно проверено окно **900×760 без устройства**,
а также заполненные тестовые карточки каталога, отключённая запись, выбранный
комплект клавиатур, запись по таймеру и её результат.

Тестовые карточки существовали только в отдельном временном профиле; публичный
каталог ими не заполнялся. Живые ADB-команды на автомобиле не выполнялись.

Основные действия файлов, приложений и терминала закреплены; дополнительные
команды доступны через «Ещё». На узком окне навигация сворачивается в панель
значков. Снимки проверены на перекрытия, обрезанные действия, контраст и
равномерность отступов. Источники и технические значения сохраняются для экспорта.

## Сохранность функций

Команды ADB, установочные сценарии, формат каталога, код входа и закрепление
устройства сохранены. Изменена очистка уже завершённого процесса, чтобы ошибка
запуска не оставляла недействительный объект в списке отменяемых заданий.
Профиль обновляет следующие операции; уже начатая установка или восстановление
не прерывается из-за смены административных настроек.

Подробные данные каждого запуска находятся в `dist/release_manifest.json`.
Подключение публикации каталога из административного окна проверено на имитаторе
GitHub API. Реальные публикация проекта, CI, скачивание выпуска и чтение публичного
каталога выполнены через существующий GitHub-репозиторий.

## Границы проверки и известные ограничения

Автомобиль не подключался. Имитация успешной замены файла, записи настроек или
загрузки после reboot не подтверждает работу Qinggan Settings, клавиатур,
CAN/MCU, Root и ремонтирования на конкретной прошивке.
Разбор стороннего установщика представлен в
`reverse-output/feature-audit/COMPARISON_RU.md`; его бинарник и извлечённые APK
не включаются в пользовательскую сборку автоматически.

Редизайн не заявляет исправление следующих ранее подтверждённых расхождений:

- при принятой устройством Wi-Fi-перезагрузке и потерянном ответе ADB системный
  сценарий может завершиться ошибкой раньше ожидания загрузки; изменения к этому
  моменту уже могли быть выполнены;
- ремонт Qinggan Settings не повторяет оригинал буквально: отдельного
  `adb remount` нет, добавлены остановка системы и проверенное резервирование DB/WAL/SHM;
- штатная копия клавиатуры создаётся `cp -p`, которому требуется свободное место,
  а в оригинале применяется `mv`;
- команды Root/remount/restorecon, SELinux и пути системных APK зависят от прошивки;
- «Починить verity» отключает dm-verity; оно не включает проверку системного раздела;
- после сбоя/отмены выполняются попытки возврата состояния, но при недоступном
  устройстве результат восстановления нельзя гарантировать.

Новый UI показывает назначение действий, подтверждения и журнал. Это улучшает
понятность операции, но не заменяет проверку на автомобиле. Подпись EXE и
совместимость Windows 10 должны указываться только по фактическим результатам выпуска.
