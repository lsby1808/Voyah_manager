# Voyah Manager 2.0

## Новое в версии 2.0

Левое меню содержит восемь разделов: каталог, APK с ПК, клавиатуры, инспектор,
файлы, установленные приложения, твики и терминал. На узком окне остаются значки
с подсказками. Действия файлов/приложений перенесены над таблицами; инспектор
разделён на четыре внутренние страницы. Панель подключения раскрывает настройки
ADB, Root и перезагрузки. Общий журнал, этап, прогресс и отмена доступны вне разделов.

**Админ-меню: Ctrl+Shift+Alt+A**, вход по согласованному коду. В коде приложения
хранятся только соль и PBKDF2-SHA256-хеш; проверка выполняется в рабочем потоке.
Закрытие окна заканчивает административный сеанс. Меню содержит страницы
«Функции», «Приложения», «Клавиатуры», «GitHub и публикация».

Отключённые разделы и операции остаются видимыми и неактивными. Ограничения
проверяются также в обработчиках Drag-and-Drop, горячих клавиш и установки из кэша.
Терминал управляется отдельно. Это административное управление интерфейсом,
а не защита от владельца ПК, изменяющего исходник или локальные файлы.

### Общий каталог GitHub

Начальный адрес уже встроен: https://github.com/lsby1808/Voyah_manager.
Клиент автоматически получает публичный `catalog.json` из основной ветки `main`.
Каталог пока не содержит приложений и клавиатур; ссылки добавляются владельцем
в админ-меню. Изменения записей и переключателей не требуют пересборки EXE.
Настройку другого репозитория можно сохранить отдельно на конкретном ПК.

1. Укажите публичный репозиторий `https://github.com/owner/repository`, ветку
   (пусто = основная ветка) и путь (по умолчанию `catalog.json`).
2. Сохраните подключение и GitHub fine-grained PAT с правом **Contents: write**
   к выбранному репозиторию. Токен хранится только в Windows Credential Manager
   на ПК администратора; его нет в EXE, JSON, черновиках и журналах.
3. Нажмите «Загрузить актуальный профиль». Если файла ещё нет, можно опубликовать первый.
4. Добавьте записи и переключатели, сохраните черновик, нажмите «Опубликовать».

Общий профиль применяется после подтверждённой публикации. Перед PUT проверяется SHA;
конфликт требует загрузки актуальной версии, локальный черновик сохраняется.
Профиль обновляется при запуске, по кнопке и каждые пять минут с HTTP ETag.
Последний корректный профиль и проверенные скачанные файлы доступны без сети.
Во время активной операции применение нового профиля откладывается до её завершения.

JSON: `schema_version: 1`, `revision`, `features`, `apps`, `keyboards`.
`catalog.example.json` содержит пустой профиль с реестром функций. Приложение имеет
ID, название, описание, source, asset, package, min_sdk, enabled и post_install.
Единственное дополнительное действие — `request_install_packages`.
Клавиатура имеет central_url/passenger_url, models, min_sdk и необязательные
central_sha256/passenger_sha256. Команды shell и системные пути из JSON запрещены.

Репозиторий разрешается в последний стабильный релиз; ссылка на релиз закрепляет
версию. При нескольких APK предлагается выбор; asset задаёт точное имя файла.
Поддерживаются прямые APK/APKS/XAPK/APKM. Загрузки атомарны: `.part` не считается
готовым файлом. Размер и SHA-256 сверяются, когда источник их предоставляет;
для кэша дополнительно хранится и повторно проверяется локальный хеш.

Общий установщик используется каталогом и локальной страницей. APK из памяти ГУ
сначала скачивается для проверки AAPT2. На распознанном Voyah проверяется
`sys.config.app_install_disabled`, при блокировке задаётся `false` с проверкой;
используется `--no-streaming`. По умолчанию `-r -g`. После Success проверяются
pm path и versionCode. Для фактического `ru.vk.store` автоматически выдаётся и
проверяется `REQUEST_INSTALL_PACKAGES allow`. Повторной установки после потери
связи нет. За заданием закреплён конкретный serial.

### Клавиатуры и восстановление

Комплект содержит два APK пакетов `com.qinggan.app.qgime` и
`com.qinggan.app.qgime.second`. Проверяются API, ABI, версия, штатные файлы и модели
`f0506h`, `f6802h`, `f0505h`, `f6804h`. После отдельного подтверждения:
Root → disable-verity → sync/reboot → ожидание Android → Root → remount → временный
Permissive SELinux. Изменяются только QGIME-release-signed.apk и QGIME-second-signed.apk
в их фиксированных каталогах `/system/priv-app/` из отчёта.

Существующие `.old` не перезаписываются; текущие APK дополнительно сохраняются на ПК
с проверкой SHA-256. Выставляются 0:0, 0644, restorecon, проверяется записанное
содержимое, возвращается исходный SELinux, выполняется sync/reboot и проверка пакетов.
При ошибке выполняется попытка отката к состоянию до операции, результат записывается
по экранам. «Восстановить штатные клавиатуры» возвращает `.old`, сохраняя текущие APK
на ПК. dm-verity после отката автоматически не включается.

«Починить настройки машины» останавливает Android, сохраняет и проверяет
`/data/data/com.qinggan.providers.settings/databases/qinggan_settings.db` и существующие
WAL/SHM на ПК, затем удаляет их для пересоздания и выполняет sync/start/reboot.
Если копирование не удалось, удаления не будет. После stop при отмене или ошибке
программа обязательно пытается выполнить start. Настройки автомобиля могут сброситься.

«Починить verity» явно означает **отключение dm-verity — режим из отчёта**:
Root → disable-verity → sync/reboot → ожидание sys.boot_completed.
Это действие не включает проверку разделов.

Копии и поэтапный журнал: `%LOCALAPPDATA%\Voyah Manager\backups`.
Незавершённый сценарий: `operation.json`; при следующем запуске показывается
предупреждение. В твиках есть открытие журнала и запуск Android/восстановление SELinux
на устройстве с тем же serial. Восстановление файлов при физической потере связи
может потребовать повторного подключения и ручной проверки журнала.

Начальный каталог опубликован в публичном репозитории владельца. Токен для публикации
из самой программы вводится в админ-меню и остаётся в Windows Credential Manager;
GitHub-подключение Codex не включается в EXE. Системные операции проверены имитатором
ADB; реальное ГУ не подключалось. Это не аппаратная проверка.

Переносимая утилита для работы с Android-ГУ Voyah через ADB. Целевая платформа:
Windows 10/11 x64. Интерфейс: русский и английский, переключение без перезапуска.

## Запуск

Откройте `dist/Voyah Manager.exe`. Установка Python, Qt, Java или Android Studio
не требуется. Первый запуск распаковывает встроенные инструменты и может занять
несколько секунд. Windows USB-драйвер автомобиля устанавливается отдельно,
если Windows не распознаёт ADB-интерфейс.

Приоритет ADB: сохранённый выбор, `C:\adb\adb.exe`, соседний с EXE `adb.exe`, PATH,
встроенная копия. Кнопка «Встроенный ADB» явно выбирает комплект программы.
Кэш ADB и настройки/логи: `%LOCALAPPDATA%\Voyah Manager`; настройки интерфейса
хранятся через QSettings в профиле Windows.

1. Включите отладку USB на ГУ, подключите кабель и подтвердите RSA-запрос.
2. Выберите USB и нажмите «Подключить», либо укажите IP:порт для Wi-Fi.
3. Для стандартного TCP ADB используется 5555. Пресет `Voyah :5578` подставляет
   `192.168.43.1:5578` из отчёта о стороннем установщике; он подходит не всем ГУ.
4. «USB → Wi-Fi :5555» показывает адреса ГУ и включает TCP ADB на порту 5555.

## Возможности

- Инспектор трёх дисплеев, перехват кнопок на 6 секунд, logcat и getevent,
  поиск пакетов, таблицы интентов/компонентов и сохранение логов.
- Одиночная, пакетная и split-установка; APKS через bundletool, XAPK/APKM;
  анализ манифестов AAPT2 и перенос OBB по предложению после установки.
- Файловый менеджер, push/pull, папки, переименование, удаление, установка APK
  из памяти ГУ. При активной вкладке файлов Drag-and-Drop отправляет файлы на ГУ;
  на других вкладках добавляет APK в установщик.
- Управление пакетами, запуск на центральном/пассажирском дисплее, заморозка,
  очистка данных, удаление и экспорт base/split APK.
- DPI, appops, разрешения, Doze, Private DNS, Captive Portal, Immersive.
- Терминал с историей, командами ADB и интерактивной shell.

## Особенности Android и Root

API читается с устройства: Android 9 = 28, Android 10 = 29, Android 11 = 30.
На стандартном Android 9 wm не умеет задавать DPI вторичного дисплея. Такая
операция отключается, если прошивка не предоставляет соответствующие команды.
«Все мультимедийные» = центральный + пассажирский. Приборная панель отдельно.
Сопоставление ролей и Display ID доступно во вкладке твиков.

«Расширенный режим» позволяет явно вызвать adb root, проверить su (варианты
`su sh -c` и `su -c`) и выполнить adb unroot. Программа проверяет фактический UID.
Успех зависит от прошивки и доступных прав. Обычные операции не повышают права
автоматически; системные сценарии получают Root после отдельного подтверждения.
Доступ к CAN/MCU через logcat/getevent не гарантирован.

pm clear удаляет данные приложения вместе с кэшем. Отмена обычного задания
останавливает текущий процесс и оставшиеся шаги; применённые изменения остаются.
Системные сценарии выполняют описанные выше действия восстановления состояния.
Для сетевых настроек сохраняются исходные значения с возможностью восстановления.
Кнопка скриншота по умолчанию снимает основной экран SurfaceFlinger; номера
логических экранов Android и физических экранов SurfaceFlinger могут отличаться.

## Проверки и ограничения

Реального ГУ при разработке нет. Автоматические проверки выполняются на
имитаторе ADB, тестовых дампах, реальном AAPT2 и bundletool; EXE проверяется
на текущей Windows 11 x64. На Windows 10 и конкретной прошивке автомобиля
требуется дополнительная проверка. Готовый EXE не имеет цифровой подписи.

Демонстрация без устройства: `"Voyah Manager.exe" --demo`.
Этот режим явно обозначен; команды в нём имитируются.

## Сборка из исходников

Код приложения целиком в `voyah_manager.py`. Вспомогательные скрипты относятся
к подготовке сборки и тестированию.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe prepare_tools.py
.\.venv\Scripts\python.exe -m pytest tests -s -q
.\.venv\Scripts\python.exe build_exe.py --onedir
.\.venv\Scripts\python.exe build_exe.py
```

Для воспроизведения точно того же набора Android/Java инструментов сохраняйте
`tools/manifest.json` и `tools/versions.json`: скрипт загрузки может получить
более новую версию Platform Tools или Temurin при будущей пересборке.

Тексты сторонних лицензий и ссылки на исходники: `THIRD_PARTY_NOTICES.txt`.
Тестовый `upstream.apk` происходит из google/bundletool 1.18.3 (Apache 2.0),
используется только в тестах и не включается в пользовательский EXE.
