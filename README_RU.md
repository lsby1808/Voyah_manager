# Voyah Manager 2.1.2

Обновление 2.1.2 добавляет текущий пароль инженерного меню в верхней панели.
Нажмите на него, чтобы увидеть дату по Пекину, варианты на соседние дни и скопировать
пароль. В админ-меню на странице «Функции» появился локальный демонстрационный режим
с применением через перезапуск. Он имитирует команды автомобиля и сохраняется
только на этом ПК. Перед переключением завершите задания и остановите наблюдение.

В «APK с ПК» способ установки определяется автоматически по сведениям внутри APK:
разные приложения устанавливаются по очереди, части одного пакета и версии — вместе.
На странице кнопок руля убрана большая пустая область; запись и результат оформлены
отдельными компактными карточками.

Обновление 2.1.1 делает «APK с ПК» компактной рабочей областью: очередь сразу под
перетаскиванием, удаление файлов по одному, подтверждение добавления и защита от
дубликатов. Технический блок убран; параметры и установка всегда рядом со списком.
Исправлены выравнивание пояснения клавиатур, линия вкладок инспектора, значки
пустых состояний и фон закладок файлов. Пресеты масштаба расширены до 80–260
с понятными подписями; ручное значение проверяется в том же диапазоне.

Voyah Manager — переносимое приложение для Windows 10/11 x64, которое помогает
устанавливать приложения, работать с файлами и настраивать мультимедийную систему
Voyah. Русский и английский переключаются без перезапуска. Python, Qt, ADB,
инструменты проверки APK и Java входят в сборку EXE.

Версия 2.1 перерабатывает интерфейс существующих функций: единые скругления,
контурные значки, плавные переходы, понятные пояснения, карточки приложений и
сценарный инспектор. Изменение оформления не означает новой аппаратной проверки
или исправления всех ранее обнаруженных особенностей системных сценариев.

## Первый запуск и подключение

Откройте `dist/Voyah Manager.exe`. При первом запуске распаковка встроенных
инструментов может занять несколько секунд. Если Windows не распознаёт ADB-интерфейс
автомобиля, соответствующий USB-драйвер устанавливается отдельно.

В верхней панели видны выбранная машина, текстовый статус подключения, кнопка
«Подключить» и язык. По пожеланию пользователя мини-пульт из этой панели убран.
Наведите указатель на значок, чтобы прочитать пояснение. Цвет статуса дублируется
текстом: возможность подключения не нужно определять только по цвету.

1. На ГУ включите отладку USB, подключите кабель и подтвердите запрос доверия
   компьютеру, если он появился на экране автомобиля.
2. Нажмите значок настроек подключения в верхней панели. Выберите USB или Wi-Fi,
   нужное устройство и, для Wi-Fi, адрес машины.
3. Нажмите «Подключить» и дождитесь определения параметров автомобиля.
4. При нескольких подключённых устройствах внимательно выберите нужное.
   Выполняющееся задание закрепляется за конкретным устройством.

Стандартный порт Wi-Fi ADB — 5555. Пресет `Voyah :5578` подставляет
`192.168.43.1:5578` из отчёта о стороннем установщике; он подходит не всем прошивкам.
«USB → Wi-Fi :5555» показывает найденные адреса и включает сетевой ADB. Для этого
действия сначала нужно подключиться по USB.

В раскрываемых настройках доступны перезапуск связи, расширенный доступ и
варианты перезагрузки. Используется только встроенный ADB: выбирать или
устанавливать его отдельно не нужно. Сохранённый ранее путь к внешнему ADB
игнорируется. Встроенные файлы проверяются и подготавливаются в фоне.

## Как устроен новый интерфейс

Левое меню объединяет восемь разделов в три группы:

| Группа | Разделы | Для чего нужны |
|---|---|---|
| Приложения | Каталог приложений, APK с ПК, Клавиатуры | Выбрать готовое приложение, установить свои файлы или заменить клавиатуры двух экранов |
| Автомобиль | Инспектор, Файлы, Установленные приложения, Твики | Посмотреть работу экранов, обменяться файлами и настроить установленное ПО |
| Для опытных | Терминал | Выполнить собственные команды на выбранной машине |

При уменьшении окна меню становится компактным: названия заменяются значками,
а пояснения остаются в подсказках. Карточки перестраиваются по доступной ширине.
Таблицы файлов и установленных приложений прокручиваются отдельно от основных
действий, чтобы управление оставалось под рукой.

В нижней панели всегда доступны текущий этап, индикатор выполнения и отмена.
Кнопка «Журнал операций» раскрывает подробную запись действий и ответов автомобиля.
Основные результаты также появляются в текстовом сообщении рядом с панелью.
Для некоторых этапов точный процент неизвестен — тогда показывается индикатор
выполнения, а не выдуманное значение.

Плавные переходы разделов и раскрытие меню можно убрать: в настройках подключения
включите «Уменьшить анимацию». Программа также учитывает системную настройку
анимаций Windows. Функции продолжают работать при отключённых эффектах.

Большинство кнопок имеет подсказку с обычным объяснением результата. Если действие
запретил администратор, оно остаётся видимым и неактивным. Для операций, которым
нужно подключение или выбранный объект, сначала подключите машину либо выберите
строку или карточку.

## Установка приложений

### Готовые приложения из каталога

Откройте «Каталог приложений», найдите нужную карточку и нажмите «Выбрать приложение».
Снизу появятся описание выбранного приложения и сведения о совместимости.
«Скачать и установить» загружает файл, проверяет его и передаёт установщику.
Если выпуск содержит несколько подходящих файлов, программа предложит выбор.

Начальный каталог: [lsby1808/Voyah_manager](https://github.com/lsby1808/Voyah_manager).
Список приложений, клавиатур и доступных функций задаёт администратор.
«Обновить каталог» получает опубликованные изменения. Каталог также обновляется
при запуске и каждые пять минут. Без интернета используются последний корректный
профиль и ранее скачанные файлы, прошедшие проверку локального хеша.

Неполный файл загрузки не считается готовым. При наличии данных источника
проверяются размер и контрольная сумма. Надпись о предварительной совместимости
не заменяет окончательную проверку самого APK перед установкой.

### APK с компьютера

В разделе «APK с ПК» программа сама определит способ установки:

- один APK — одно приложение;
- пакетная установка — несколько независимых приложений по очереди;
- split/архив — одно приложение, состоящее из нескольких частей.

Добавьте файлы, выберите папку или перетащите APK/архивы в окно. Проверьте очередь
и нажмите установку. По умолчанию сохраняются данные при переустановке и выдаются
разрешения, которые приложение запросило и система позволяет выдать.
Понижение версии включается отдельно.

Поддерживаются APK, APKS, XAPK и APKM. Для APKS с `toc.pb` набор частей подбирается
с учётом параметров устройства через bundletool. Для XAPK перенос дополнительных
OBB-файлов предлагается отдельным этапом после установки приложения; результат
копирования показывается отдельно.

Общий установщик проверяет пакет, минимальную версию Android, архитектуру и
состав частей. На распознанном Voyah снимается поддерживаемая прошивкой блокировка
установки и применяется `--no-streaming`. После успешного ответа проверяются
фактическое наличие пакета и версия. Для RuStore (`ru.vk.store`) дополнительно
выдаётся и проверяется право установки других приложений.

Если связь потерялась и итог установки неизвестен, оставшиеся шаги останавливаются.
Программа не начинает такую установку повторно автоматически.

## Клавиатуры двух экранов

Выберите комплект в разделе «Клавиатуры». Две карточки объясняют, какой файл
предназначен центральному экрану, а какой — пассажирскому. Программа заранее
скачивает и проверяет оба файла. Пока комплектов нет, показывается пояснение;
восстановление штатных клавиатур расположено отдельно.

Комплект заменяет два системных APK, а не ставит обычную клавиатуру как пользовательское
приложение. Проверяются пакеты `com.qinggan.app.qgime` и
`com.qinggan.app.qgime.second`, версии файлов, API, архитектура, модель и наличие
штатных файлов. Начальный список моделей: `f0506h`, `f6802h`, `f0505h`, `f6804h`.

Перед заменой показывается подтверждение с резервными копиями и перезагрузками.
Сценарий выполняет Root → отключение dm-verity → сохранение изменений и перезагрузку
→ ожидание Android → повторный Root → remount → временное изменение SELinux.
Заменяются только два фиксированных файла из отчёта в `/system/priv-app/`.

Штатные `.old` не перезаписываются. Текущие файлы дополнительно сохраняются на ПК
и проверяются по SHA-256. После записи проверяются содержимое, владелец и права,
восстанавливаются контекст и исходный режим SELinux, затем выполняется перезагрузка
и проверка пакетов. При ошибке программа пытается вернуть уже изменённые файлы
к состоянию до операции и записывает результат в журнал.

«Восстановить штатные клавиатуры» возвращает сохранённые `.old`, предварительно
копируя текущие APK на компьютер. Проверка dm-verity после отката автоматически
не включается. Поддержка Root, remount и команд проверки зависит от прошивки.

## Инспектор: что происходит в автомобиле

Инспектор организован по задачам, а не только по именам диагностических команд.

**Экраны.** Обновите сведения и посмотрите, какое приложение открыто на приборном,
центральном и пассажирском экранах. Карточки показывают роль экрана и найденное
приложение. Технические адреса можно раскрыть и скопировать отдельно. Если автомобиль
не сообщил сведения, показывается понятное пустое состояние.

**Кнопки руля.** Нажмите «Начать запись на 6 секунд», дождитесь начала отсчёта и
нажмите нужную кнопку в машине. После записи сообщения группируются: открытые
экраны, кнопки и голосовые действия, фоновые действия, все сообщения. Запись можно
сохранить или открыть в Блокноте. Одно нажатие может давать несколько сообщений.

**Наблюдение в реальном времени.** «События приложений» и «Нажатия кнопок» запускаются
и останавливаются независимо. Фильтр скрывает ненужные строки на экране, а полная
сохранённая запись остаётся доступна. Пауза прокрутки удерживает нужные строки для
чтения и не останавливает получение сообщений.

**Сведения о приложении.** Найдите приложение по части его адреса или укажите адрес
вручную, затем получите сведения. Отдельно показываются экраны приложения,
получаемые события и фоновые действия. Полный диагностический ответ доступен для
сохранения и подробного разбора.

Некоторые кнопки руля работают через CAN/MCU в обход Android input и доступных
журналов. Пустая запись не доказывает, что кнопка сломана. Доступ к сигналам кнопок
также может быть закрыт прошивкой; причина отказа показывается в результате.

## Файлы, установленные приложения и твики

В «Файлах» доступны закладки памяти, переход по папкам, передача на автомобиль и
скачивание на компьютер. Выберите строку для действий с файлом. В меню «Ещё»
находятся создание папки, переименование, установка выбранного APK и удаление.
Удаление требует подтверждения. Перетаскивание файлов на открытый раздел «Файлы»
отправляет их в текущую папку ГУ; на других разделах добавляет APK в установщик.

«Установленные приложения» позволяет искать и фильтровать пакеты, открывать приложение
на центральном или пассажирском экране, останавливать его и сохранять APK на ПК.
Меню «Ещё» содержит временное отключение/включение, очистку данных и удаление.
**Очистка удаляет данные приложения вместе с кэшем.** Системное приложение может
отвечать за функции автомобиля; перед его изменением нужно понимать назначение.

«Твики» разделены на четыре группы:

- **Масштаб и дисплеи:** текущие параметры, изменение размера элементов, заводской
  масштаб и сопоставление ролей экранов.
- **Аудиофокус и разрешения:** паузы музыки, микрофон, окна поверх экрана, доступ
  к настройкам и фоновая работа выбранного приложения.
- **Сеть и система:** фильтр рекламы AdGuard, предупреждение Wi-Fi без интернета,
  верхняя панель и открытие обычных настроек Android. Для обратимых настроек
  предыдущие значения сохраняются при первом изменении и доступны для возврата.
- **Восстановление системы:** пересоздание настроек машины, отключение dm-verity,
  журнал и возобновление Android после прерванной операции.

«Все мультимедийные» изменяет центральный и пассажирский экраны. Приборная панель
выбирается отдельно и требует подтверждения. Стандартный Android 9 не поддерживает
адресное изменение DPI вторичного дисплея; соответствующая операция недоступна,
если прошивка не предоставляет такую возможность.

«Починить настройки машины» останавливает Android, сохраняет и проверяет базу
Qinggan Settings вместе с существующими WAL/SHM на ПК, затем удаляет их на ГУ для
пересоздания. При ошибке копирования удаления не будет. После остановки Android
при отмене или сбое выполняется попытка запуска системы. **Личные настройки
автомобиля могут сброситься.**

«Починить verity» означает **отключение dm-verity по процедуре установщика**:
Root → `disable-verity` → `sync` → перезагрузка → ожидание загрузки.
Это действие не включает заводскую проверку разделов.

В «Терминале» доступны история, произвольные ADB-команды и интерактивная shell-сессия.
Команда без собственного селектора использует выбранный автомобиль. Работа с
терминалом рассчитана на пользователя, понимающего действие введённой команды.

## Админ-меню и общий каталог

Вход: **Ctrl+Shift+Alt+A**, затем согласованный секретный код. Код не показывается
в документации, каталоге и журналах. В приложении хранится проверочный хеш с солью,
а проверка выполняется в рабочем потоке. Закрытие админ-окна заканчивает сеанс.

Админ-меню имеет четыре страницы:

1. **Функции:** доступность разделов и операций, сгруппированных по назначению.
   Сам вход администратора и чтение статуса подключения отключить нельзя.
2. **Приложения:** добавление названия, описания, источника и необязательных сведений
   для проверки приложения. Источник — репозиторий, выпуск GitHub или прямой файл.
3. **Клавиатуры:** название комплекта и две ссылки для двух экранов.
4. **GitHub и публикация:** подключение репозитория, сохранение секрета публикации,
   загрузка актуального профиля и публикация черновика.

Для общего каталога:

1. Укажите `https://github.com/owner/repository`, ветку (пусто — основная ветка)
   и путь файла (по умолчанию `catalog.json`).
2. Сохраните GitHub fine-grained PAT с правом **Contents: write** к выбранному
   репозиторию. Он хранится только в Windows Credential Manager на ПК администратора.
3. Загрузите актуальный профиль, измените записи и функции, сохраните черновик.
4. Нажмите «Опубликовать». Общие изменения применяются после подтверждённой публикации.

Чтение публичного каталога не требует токена: используется GitHub Raw с HTTP ETag.
Публикация использует Contents API и повторную проверку SHA файла. При конфликте
локальный черновик сохраняется. Во время активного задания применение нового
профиля откладывается до завершения операции.

Формат профиля остаётся прежним: `schema_version: 1`, `revision`, `features`,
`apps`, `keyboards`. Команды shell и произвольные системные пути из каталога
не исполняются: системные сценарии определены кодом приложения.

Ограничения проверяются не только кнопками, но и обработчиками, Drag-and-Drop,
горячими клавишами и установкой из кэша. Это управление доступными функциями,
а не защита от владельца ПК, который может изменить исходник или локальные файлы.

## Данные, отмена и ограничения

Настройки, кэш и журналы: `%LOCALAPPDATA%\Voyah Manager`; настройки интерфейса
сохраняются через QSettings в профиле Windows. Резервные копии:
`%LOCALAPPDATA%\Voyah Manager\backups`. Сведения о незавершённой системной операции
находятся в `operation.json`; при следующем запуске программа сообщает о ней.

Отмена обычного задания останавливает процесс и оставшиеся шаги. Уже применённые
изменения не исчезают автоматически. В системных сценариях выполняются предусмотренные
попытки восстановления состояния; при физической потере связи они могут потребовать
повторного подключения и проверки журнала.

Реальное ГУ во время разработки не подключалось. Работа проверяется на имитаторе
ADB, диагностических дампах и настоящих инструментах обработки APK, но аппаратная
совместимость конкретной прошивки остаётся неподтверждённой.
Чек-лист: `HARDWARE_CHECKLIST_RU.md`. Отчёт интерфейса 2.1:
`QA_REPORT_V21_RU.md`; отчёт предыдущего выпуска сохранён отдельно.

Аудит стороннего установщика выявил ограничения существующих системных сценариев,
которые редизайн 2.1 не объявляет исправленными:

- потеря ответа ADB после принятой Wi-Fi-перезагрузки может завершить сценарий
  ошибкой до перехода к ожиданию загрузки; часть изменений к этому моменту уже
  могла быть выполнена;
- сценарий Qinggan Settings не полностью идентичен оригиналу: в нём отсутствует
  отдельный `adb remount`, зато добавлены остановка Android и проверенные копии;
- штатная `.old` клавиатуры создаётся копированием, которому нужно свободное место;
  сторонний установщик использует переименование;
- наличие Root, remount, restorecon и ожидаемых системных файлов зависит от прошивки;
  красивый интерфейс не подтверждает поддержку этих операций автомобилем.

Детали: `reverse-output/feature-audit/COMPARISON_RU.md`. Исследованный сторонний EXE
и извлечённые APK не входят в пользовательский комплект и не распространяются
через каталог автоматически.

Готовый EXE выпускается без цифровой подписи. Windows 10 и физический Voyah
требуют отдельной проверки; итоговые контрольные суммы находятся рядом с EXE.
Режим демонстрации: `"Voyah Manager.exe" --demo`; команды в нём имитируются и
окно явно это показывает.

## Сборка из исходников

Код приложения целиком находится в `voyah_manager.py`. Вспомогательные файлы
используются для сборки и тестирования. Зависимости закреплены в
`requirements-build.txt`; внешние инструменты — в `tools.lock.json` с проверкой SHA-256.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe prepare_tools.py
.\.venv\Scripts\python.exe -m pytest tests -s -q
.\.venv\Scripts\python.exe build_exe.py --onedir
.\.venv\Scripts\python.exe build_exe.py
```

Если upstream-файл по прежнему адресу изменился, загрузчик отклонит несовпадающий
хеш. Для перехода на другую версию инструментов нужно явно обновить lock-файл,
повторить проверки и пересобрать приложение. Итоговый `build_manifest.json`
содержит версию и хеш использованного исходника.

Сторонние лицензии и ссылки на исходники находятся в `THIRD_PARTY_NOTICES.txt`.
Тестовые APK из google/bundletool используются для проверки и не входят
в пользовательский EXE.
